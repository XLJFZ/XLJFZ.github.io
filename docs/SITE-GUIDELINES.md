# XLJFZ 摄影作品集维护规范

> 本文档是网站后续修改的约束清单。修改页面、添加照片或调整专题前，应先核对本文档，避免破坏已经确认的分类、排版、元数据和发布流程。

最后核对：2026-09-05

## 1. 网站定位与视觉基调

- 网站是 XLJFZ 的个人摄影作品集，不是通用图片瀑布流或社交相册。
- 视觉风格保持暖深灰、克制、留白充足、编辑式摄影画册感。
- 同源页面使用短暂、轻微的原生跨页淡入淡出；必须保留渐进增强，并服从系统“减少动态效果”设置。
- 桌面端内容区按页面用途使用既定最大宽度（当前为 `1400px`—`1600px`），必须保留左右页边距，不能贴边；不要为了统一数字而破坏已有版面比例。
- 移动端自然退化为单列，不保留桌面端的左右错落。
- 视觉优化必须同时检查“内容密度”和“视口利用率”：桌面首屏不能把主要交互压在上半部、在下方留下大片无意义空白；也不能为了填满屏幕而拉长纯文字区。优先调整承载核心任务的工作区高度、内部对齐和留白分配。
- 响应式高度使用少量明确断点逐级增加，手机保持紧凑、平板适度舒展、桌面与宽屏充分利用纵向空间；避免只为单一截图写死一个全局高度。
- 双栏工具工作区增高时，左侧主操作或空状态保持视觉居中，右侧说明与状态位于上部、主要操作靠近底部，让新增高度形成清晰层次而不是一整块空白。
- 所有以 `main#top` 为页面根容器并使用公共页脚的页面，必须至少占满一个动态视口高度，并采用纵向布局；短页面把页脚推到视口底部，长页面让页脚自然跟随内容。
- 公共页脚不得使用 `fixed` 或 `sticky` 定位，不能悬浮覆盖正文或工具操作区。该约束必须同时覆盖首页、关于页、作品页、工具页和 404 页面。
- 公共页头必须由 `src/components/site-header.tsx` 统一渲染，并固定在视口顶部；首页与内页保持相同的深色半透明背景、分隔线、导航状态和层级。页头后必须保留等高占位，防止固定定位遮挡正文。
- 长专题的吸顶章节导航必须保持横向可滚动，并显示当前章节、总章节和克制的进度线；直接访问 `#chapter-N` 时，导航状态必须同步。
- 图片缩略图必须保留清晰的键盘焦点反馈，不能只依赖鼠标悬停效果。
- 不使用来源不明、AI 生成或非本人作品作为封面、分享图或装饰图。

所有专题、照片顺序、尺寸、说明、地点和年份都以 [`src/lib/portfolio.ts`](../src/lib/portfolio.ts) 为唯一数据源。

| 03   | 时间的纹理 / Textures of Time | `textures-of-time` | 历史空间、木构、民艺与时间留下的表面 | 2025—2026 | 大同、应县、景德镇、徽州、西安           |      7 |

分类原则：

- 城市建筑、交通、街头秩序优先进入「城市脉冲」。
- 自然地景和天气变化优先进入「远方的天气」。
- 历史建筑、传统文化、民间艺术和材料细节优先进入「时间的纹理」。
- 人物、动物和私人日常优先进入「近处发生」。
- 不要仅因新增一两张照片就随意创建第五个专题；只有题材明确独立且已有足够作品时再讨论新专题。

## 3. 照片排序与桌面端配对规则

画廊由 [`src/components/lightbox-gallery.tsx`](../src/components/lightbox-gallery.tsx) 统一渲染。

必须遵守：

1. 先按 `chapter` 分章节，同一地点或叙事段落不能跨章节配对。
2. 同一章节内优先把竖构图与竖构图、横构图与横构图配成一行。
3. 如果章节最后只剩一横一竖，则两张仍组成同一行，不能拆成左右错落的两行。南昌两张照片就是这一规则的基准案例。
4. 同行照片必须同顶线、同底线。通过轻微调整各自显示宽度实现等高，不能裁切照片。
5. `layout: 'wide'` 是明确的重点作品，应跨列独立展示，不参与普通配对。
6. 只有总数为奇数且没有可配对象时，才允许出现单张错落布局。
7. 禁止恢复“同行固定相同宽度”的旧做法；不同长宽比会因此造成底边不齐。
8. 禁止用人为的顶部外边距制造错落，这会破坏章节对齐。

当前实测基准：四个专题所有双列行的上下边缘误差均为 `0px`。

## 4. 移动端规则

- `md` 断点以下统一为单列，照片宽度服从可用内容宽度。
- 不在移动端强行保留桌面端等高宽度计算。
- 页面不能出现横向滚动条。
- 灯箱底部的 caption 与序号必须处于同一行并避免重叠。
- 触控左右滑动、键盘方向键和关闭按钮都必须保留。
- 灯箱黑色背景必须覆盖整个视口；图片自身保留呼吸空间。点击图片之外的黑色区域可关闭灯箱，点击图片与控制按钮不得误关闭。
- 灯箱底部可显示真实 EXIF，顺序固定为“机身 · 焦段 · 光圈 · 快门 · ISO”；视觉权重低于地点和年份。只显示文件中确认存在或由用户明确补充的字段，缺失项不得猜测。

## 5. 元数据与文字规则

- 拍摄时间只使用真实 EXIF `DateTimeOriginal` 或 `CreateDate`，绝对不能根据文件名猜测。
- 用户明确确认的地点或年份可作为权威补充；未确认的地点不要推断。
- 单张说明统一优先使用 `地点 · 年份`，例如 `徽州 · 2026`。
- 专题的 `year` 必须覆盖其中所有照片的真实年份；新增跨年作品后同步更新范围。
- 专题的 `location` 必须覆盖其中所有已确认地点。
- `width`、`height` 必须填写照片的真实像素尺寸，不能填写页面显示尺寸。
- `alt` 只描述画面中可见的内容，不虚构事件、身份或地理细节。
- 新文件使用稳定、可读的小写名称：`地点-相机或编号.jpg`。
- 加图前检查 `public/portfolio` 与 `src/lib/portfolio.ts`，避免重复加入此前的上海、西安或其他照片。

### 5.1 EXIF 证据与写入规范

灯箱 EXIF 的唯一写入位置是 `src/lib/portfolio.ts` 中对应照片记录的 `exif` 对象。网页用 JPEG 与生成的预览图可能已清除元数据，不能因此覆盖已核实的记录。

证据优先级：

1. 与网站作品明确对应的 RAW / DNG 原片。
2. 保留了完整元数据的导出图片。
3. 用户明确指定照片对应关系后提供的参数或截图。

必须先确认原片与网站文件的一对一关系，再写入数据。文件名、拍摄目录、相邻编号、相同镜头或同场景只能用于定位候选原片，不能单独作为填写某个 EXIF 字段的证据。

灯箱只允许以下五个字段，并按固定顺序显示：

| 字段           | 内容     | 格式示例                    |
| -------------- | -------- | --------------------------- |
| `camera`       | 机身     | `Nikon Z7 II`、`Sony α7 IV` |
| `focalLength`  | 实际焦距 | `26mm`、`9mm（等效 24mm）`  |
| `aperture`     | 光圈     | `f/2.8`、`f/8`              |
| `shutterSpeed` | 快门     | `1/500s`、`60s`、`900s`     |
| `iso`          | 感光度   | `ISO 64`、`ISO 12800`       |

- 相机型号可以规范化为公开产品名，例如 `NIKON Z 7_2` 写为 `Nikon Z7 II`、`ILCE-7M4` 写为 `Sony α7 IV`。无法唯一对应的内部型号不得自行改写；优先使用用户明确确认的展示名称。
- 焦距默认写实际焦距。只有原文件或用户明确提供等效焦距时，才在后面补充“等效”值。
- 不保存空字符串、`unknown` 或占位符。某个字段无法核实时直接省略，已核实的其他字段可以正常显示。
- 不向网站写入或展示 GPS、机身/镜头序列号、所有者信息、编辑历史、完整拍摄时刻等与灯箱展示无关或可能暴露隐私的元数据。
- 只读取核对所需的最少原片，不把 RAW / DNG、XMP 或用户的原始目录复制进网站仓库。
- 每次新增 EXIF 后，同步更新 `tests/portfolio-gallery.test.mjs` 中的 EXIF 记录总数和该照片的五字段断言，防止以后错配或意外删除。

## 6. 图片资产结构

```text
public/portfolio/                    原始展示照片；灯箱读取这里
public/portfolio/<series-slug>/      按专题保存原图
public/portfolio-previews/           画廊响应式预览，脚本生成
public/hero-previews/                首页主视觉响应式预览，脚本生成
public/covers/                       首页和专题索引使用的轻量封面
```

- 新增或替换原图后必须运行 `npm run previews`。
- 预览图由 [`scripts/generate-gallery-previews.mjs`](../scripts/generate-gallery-previews.mjs) 生成：宽度 `1200px` 与 `1800px` 两档、JPEG 质量 `90`、`4:4:4` 色度采样；列表优先使用预览图，灯箱才加载原图。
- 首页主视觉同时生成 `1280px` 与 `2200px` 两档预览，浏览器按屏幕宽度选择；移动端禁止直接下载 `3000px` 原图。
- 首页、专题索引与“下一组作品”的专题封面同时提供 `1200px` 移动版和高分辨率桌面版，必须通过 `srcset` 与 `sizes` 让浏览器按版面选择。
- 不要手工修改生成的预览图，也不要让画廊首屏直接下载全部原图。
- 长专题首章之后的屏幕外章节使用渐进增强的延迟绘制；必须保留章节锚点与不支持该能力的浏览器回退，不能通过卸载 DOM 破坏灯箱顺序。
- 章节高亮使用浏览器可见性观察器跟随章节标记，禁止恢复为滚动时持续读取全部章节位置的监听器。
- 灯箱继续加载原始展示照片，以保留放大观看质量。
- 灯箱先显示已缓存的 `1800px` 预览，再平滑切换到原图，避免黑屏闪烁；移动端控制按钮必须避开设备安全区域。
- 全局视口必须启用 `viewport-fit=cover`，让 iPhone 刘海屏和圆角安全区域样式真正生效；原图失败时保留高清预览，不显示空白。
- 专题封面建议为 `2400 × 1500`，并保持在 `1MB` 以内。

### 7.1 摄影习惯分析规则

- 工具工作区在页头与页脚之间垂直居中；短内容不能贴住页头，长内容仍须自然延伸，不能使用固定高度裁掉结果。
- 初始上传工作区必须使用响应式最小高度，当前基准为手机 `360px`、平板 `420px`、桌面 `520px`、宽屏 `560px`。后续调整可以根据真实视口优化，但必须保持逐级舒展，并由 `tests/photo-habits.test.mjs` 保护，不能退回桌面端局促、下方留出大片空白的布局。
- 工具支持本地拖入 JPEG、TIFF、DNG、NEF、ARW、CR2、富士 RAF 与哈苏 3FR / FFF；不支持的文件必须明确忽略或提示。
- 所有照片解析与统计都在浏览器本地完成，不上传原片、预览图或 EXIF；界面只能展示统计结果和用户主动选择加载的站内公开照片。
- 统计焦段、光圈、ISO、快门与拍摄时间时，缺失字段必须排除，不能当作 `0` 计入分布。
- “你考虑的镜头”至少保留 `10mm`、`12mm`、`135mm`、`100–400mm`、`400mm+` 和自定义范围；调整预设时必须同步更新测试。
- 镜头购买建议只能基于可用焦段样本数量与落入候选范围的真实比例。样本不足时必须明确说明，不得给出确定性购买结论。
- 富士 RAF 可从内嵌 JPEG 读取标准 EXIF；哈苏 3FR / FFF 按 TIFF 系列容器尝试读取。解析失败时应报告缺少可读元数据，不能补造参数。
- 相关隐私、本地处理、格式支持、镜头预设和建议边界由 `tests/photo-habits.test.mjs` 保护。

### 7.2 照片批量压缩规则

- 工具只接受 JPG / JPEG，并允许一次选择或拖入多张照片；非 JPEG 文件必须明确忽略或报错，不能静默转换。
- 所有读取、压缩和打包都在浏览器本地完成，不把照片发送到网站服务器或第三方服务。
- 原文件不得覆盖。输出文件统一增加 `-web.jpg` 后缀，并以 ZIP 下载。
- 压缩内核使用 `compressorjs`，必须保持 `retainExif: true` 与方向校正，不能改回会清除 EXIF 的裸 Canvas 导出。
- 界面只提供三档，不重新引入连续质量滑杆：

| 档位 |   最长边 | JPEG 质量 | 用途               |
| ---- | -------: | --------: | ------------------ |
| 轻量 | `1600px` |      `76` | 文章配图与更快加载 |
| 推荐 | `2400px` |      `82` | 摄影网站默认选择   |
| 大图 | `3200px` |      `86` | 全屏查看与更高细节 |

- 如果原文件没有 EXIF，工具不得补造元数据；如果原文件有 EXIF，输出应继续保留。
- “保留 EXIF”包含原文件中可能存在的 GPS、序列号、所有者信息和完整拍摄时间。界面必须持续显示这一提醒，不能只写“保留拍摄参数”。
- 工具不会自动上传或提交输出文件。准备将结果放入公开仓库前，仍需按 5.1 节检查隐私；含 GPS 或序列号的文件不能因为经过压缩就被视为可安全公开。
- 本节描述的是下载文件内的元数据保留；作品灯箱仍只允许展示 5.1 节规定的五个字段，两者不能混为一谈。

### 7.3 智能照片批量命名器规则

- 页面路由为 `/tools/photo-renamer/`，接受浏览器可读的 JPEG、PNG 与 WebP，支持点击选择和批量拖入。所有读取、命名和 ZIP 打包都在浏览器本地完成，不上传照片、预览图、EXIF 或用户填写内容。
- 自动字段只能来自真实可读的 EXIF：日期只取 `DateTimeOriginal` 或已有解析器认可的拍摄时间，相机只取机身型号。无可靠 EXIF 时必须显示缺失状态并保持空白，不得从文件名、文件修改时间或相邻照片猜测。
- 文件名结构固定为“日期-地点-主题-相机或编号-三位连续号.扩展名”，并自动省略空字段。连续号从 `001` 开始，按当前列表顺序稳定生成；保留原扩展名并统一转为小写。
- English 模式将人工输入规范为小写 ASCII 与连字符，去除重音符号和不安全标点；中文模式保留中文字符，用连字符代替空格和文件系统不安全字符。切换语言后必须立即重算全部预览名称。
- 用户可逐张修改日期、相机或编号、地点和主题；人工值是当前会话的最终依据，必须立即覆盖对应 EXIF 或预设值。地点与受控主题词表可批量应用；主题同时保留“直接填写”入口，手写值覆盖预设主题。
- 受控词表当前包含建筑、街道、山景、海岸、夜景、人物、动物、室内和细节，并必须保持中英文一对一映射。调整词表时同步更新 `src/lib/photo-renamer.ts`、界面选项和聚焦测试。
- 每张照片都必须显示原名称、完整新名称和主要证据字段。新名称重复时显示明确错误并禁用下载；用户修正后自动恢复。
- ZIP 下载只包含按新名称存放的字节级原图副本，不重编码、不改写 EXIF、不删除用户本地文件，也不覆盖原文件。这不等于照片已经通过隐私检查；公开发布前仍需单独使用照片隐私检查器。
- 下载提供四个简单选项：默认“不压缩”只重命名并保留原始字节和格式；“轻量”使用 `1600px/76`、“推荐”使用 `2400px/82`、“大图”使用 `3200px/86`。三档压缩统一输出 JPEG，并沿用 `compressorjs` 的 `retainExif: true`、`checkOrientation: true` 与 `strict: false`；PNG 和 WebP 选择压缩后会转为 JPEG，界面与新名称扩展名必须同步说明这一变化。
- 当前基础版不集成语义模型。经评估，可靠的 CLIP 零样本模型首次加载约 `350 MB`，对当前静态 GitHub Pages、移动网络和低内存设备过重。未来如果引入增强，必须由用户主动加载，只从受控词表返回带置信度的“建议”，低置信度保持待确认且不写入文件名。不得用主色、亮度、文件名或其他弱特征冒充语义识别。
- 命名语法、中英文规范化、重名检测、本地处理、人工修改和语义模型边界由 `tests/photo-renamer.test.mjs` 保护。

### 7.4 其他工具与回归检查

- 照片质量初筛器路由为 `/tools/photo-quality/`，支持 JPEG、PNG、WebP、TIFF，以及 DNG、NEF、ARW、CR2、RAF、3FR/FFF。所有文件逐张在浏览器本地处理，不上传、不修改原文件；处理后须关闭 `ImageBitmap`，临时下载完成后须撤销对象 URL，避免大批量文件形成内存峰值。
- RAW 像素指标使用容器中可找到的最大内嵌 JPEG 预览。没有浏览器可解码预览时必须明确显示“像素分析不可用”，不得把缺失结果当作零值，也不得声称已分析传感器原始数据。
- 清晰度风险使用缩小灰度图的拉普拉斯方差，高光与暗部剪切分别统计接近纯白和纯黑的像素比例；同时报告实际解码像素尺寸与低分辨率提示。界面只提供宽松、推荐、严格三档，并持续显示当前数值阈值。
- 完全重复使用文件字节的 SHA-256 分组；近似重复使用 64 位感知哈希与汉明距离，不得按文件名推断。结果页须提供总览、问题分类、单张数值依据、重复组和 CSV 报告。
- 所有提示只用于人工初筛，不构成审美评分，不能自动删除、淘汰或覆盖照片。必须持续提示长曝光、浅景深、夜景、高调和低调作品可能被误报，并保留用户最终判断。以上边界由 `tests/photo-quality.test.mjs` 保护。

- 照片隐私检查器接受 JPG / JPEG、JPEG XL、HEIC / HEIF、AVIF、WebP 与 TIFF；检查和清理全程在浏览器本地完成，不上传照片或元数据。输出在原扩展名前增加 `-clean` 且不能覆盖原文件。
- 默认选择 GPS、设备标识、所有者、拍摄时间、备注与编辑信息五类隐私项，允许逐类取消；未选中的曝光参数、相机型号等 EXIF 应保留。
- 清理设备标识时必须同时移除厂商私有信息，因为机身序列号可能只存在于 MakerNote；生成下载前必须重新解析副本并确认所选类别不再出现。
- 该工具直接定位各容器内可读的 TIFF / EXIF 数据并原位清理，不重编码图像数据，因此保持原始像素与画质。当前不处理相机 RAW、PNG、GIF、独立 XMP 边车文件或 JPEG XL 的 Brotli 压缩 EXIF；不能把“未发现”描述成文件绝对不含任何其他元数据。
- 隐私检查器的类别、标签范围、本地处理、原图保护与复查约束由 `tests/exif-privacy.test.mjs` 保护。

- 色彩样本提取器允许一次导入一张或多张浏览器可读取的图片，分别显示单张主色与综合色板，并按有效采样像素汇总整组色板和暗部、中间调、亮部比例。
- 色彩分析只在浏览器本地使用缩小后的 Canvas 像素采样，不上传照片、不修改原文件、不写入元数据，也不把结果自动保存到网站。
- 色板用于系列封面选择、页面底色和视觉重量判断。结果受浏览器解码、缩小采样、显示器与色彩空间影响，不能作为印前打样或专业色彩测量结果。
- 工具保持直接选择和拖入两个入口，不增加聚类参数、取样数量、亮度阈值等连续控制项；综合色板固定显示最多八色，单张色板最多六色。
- `tests/color-sampler.test.mjs` 必须验证主色与明暗计算、整组权重汇总、本地处理边界和页面说明。

- 社交平台裁切预览器必须在浏览器本地读取图片，保持各比例的主体位置互不影响，并允许用户选择需要的比例后单张或 ZIP 导出；输出不覆盖原文件。
- 默认比例包含 1:1、4:5、9:16、5:7、4:3、3:2、16:9、16:10、1.91:1、65:24 与 2.35:1，并保留自定义宽高入口。
- 裁切导出会重新编码为 JPEG，不承诺保留 EXIF；这一点有助于减少公开社交图片携带位置等隐私信息，但不能替代发布前检查。
- 智能命名器、照片压缩器和社交裁切器在形成结果或完成下载后，必须在主要操作附近显示统一且克制的“下一步：检查照片隐私”入口，链接到 `/tools/exif-privacy/`。入口不得遮挡下载按钮，也不得暗示前一步已经清除了敏感信息。

- 打印尺寸计算器按纸张物理尺寸估算最大打印尺寸、有效 DPI、铺满裁切比例和完整保留画面尺寸；推荐精度须考虑成品尺寸与通常观看距离，A2、A1、A0 分别默认建议 240、200、150 DPI，不能把超大幅面一律按 300 DPI 判断。结果不包含打印机不可打印边距、出血和装裱余量。
- 新增站内工具时，必须同步更新主导航、`scripts/export-github-pages.mjs`、`public/sitemap.xml` 和对应测试。
- 照片压缩工具的基础约束由 `tests/image-compressor.test.mjs` 保护：本地处理、EXIF 保留、三档预设和无连续滑杆。
- 社交平台裁切工具的基础约束由 `tests/social-crop.test.mjs` 保护：默认与自定义比例、独立主体定位、本地 Canvas 导出和 ZIP 打包。
- `tests/navigation-links.test.mjs` 必须继续验证“工具”入口；`tests/github-pages-export.test.mjs` 必须继续验证工具页面被静态导出。
- 工具属于作品集的辅助能力，视觉上沿用暖深灰与编辑式排版，但首屏必须直接露出可操作区域，不能改成营销落地页。
- 工具索引在宽度不小于 `1280px` 的电脑浏览器中必须把九个工具以 `3 × 3` 完整放进一个视口；索引内容区使用扣除公共页头后的动态视口高度，卡片三行等分，并为高度不超过 `720px` 的常见笔记本视口提供紧凑间距。移动端和平板继续自然滚动，不能为追求一屏而压缩其可读性。该约束由 `tests/navigation-links.test.mjs` 保护，并须用真实桌面视口复核滚动高度。
- 工具索引卡片在桌面三列布局中使用较大的单行标题，不再人工拆成两行。编号与标题之间只保留适度的编辑式留白，正文从卡片上半部开始，详情线与箭头贴近底部，避免卡片顶部形成大面积空白；较窄视口允许标题自然换行。
- 机位与光线规划器使用 SunCalc 计算太阳、月亮及曙暮光时段，MapLibre GL JS 显示地图；角度统一采用从正北顺时针的方位角。
- 地点搜索支持国家、省州、城市和地标，并使用 OpenStreetMap Nominatim 返回最多五个候选；搜索词会发送给该服务，界面必须持续说明这一点。直接输入经纬度只在本页计算，搜索或定位后必须提醒用户核对时区。
- 机位与被摄物的经纬度都可直接编辑；地图点击和标记拖动必须同步更新坐标。定位、搜索和地图加载失败都要给出可恢复的错误提示，不能留下无说明的空地图。
- 地图提供二维平面与三维地形两种明确模式；三维模式使用地形高程并调整俯仰角，二维模式须恢复俯视。地图容器必须保留真实高度并在尺寸变化时调用 `resize`，防止 MapLibre 样式覆盖后地图塌陷。
- 地图须显示相机到被摄物的方向、太阳和月亮方位，以及由焦段、画幅和拍摄距离计算的视场角覆盖；时间轴须标出日出、日落、黄金时刻等关键节点。
- 场景光线类型按太阳相对相机—被摄物方向判断；建筑立面受光按用户设置的立面朝外法线单独判断。山体、天气、地形遮挡与建筑自身凹凸不在计算模型内，界面必须保留相应说明。
- 计划卡导出为浏览器本地生成的 PNG，不依赖地图截图或上传位置数据；导出内容须包含日出、黄金时刻、日落、蓝调和月升等关键窗口。
- GitHub Pages 导出必须把 `maplibre-gl-worker.mjs` 和 `maplibre-gl-shared.mjs` 复制到客户端 chunk 目录，并由回归测试保护，否则线上地图可能无法启动。

## 8. 灯箱与链接行为

- 点击照片后，URL 使用 `?image=<image-key>`，以便复制和分享单张照片。
- 上一张、下一张只替换当前图片参数，不能不断堆积浏览器历史。
- 浏览器“返回”应关闭灯箱并保留当前章节锚点。
- 直接访问带 `?image=` 的链接时必须自动打开对应照片。
- 灯箱 caption 在左、作品序号在右，二者不能重叠。
- 邮箱与作品链接复制使用站内轻量状态提示并保留 `aria-live` 播报；禁止重新引入全局通知系统拖慢所有页面。

## 9. 新增照片的标准流程

1. 查看工作区状态，保留用户已有但与当前任务无关的修改。
2. 检查照片是否已经存在，并在任何缩放、压缩或重新导出之前，读取真实像素尺寸、EXIF 时间和灯箱需要的五个参数。
3. 建立原片/导出图与网站文件的明确对应；按 5.1 节的证据规则处理缺失字段和型号名称。
4. 根据本文件的分类原则确定专题；地点不确定时不猜。
5. 将经选择的高质量展示图复制到相应的 `public/portfolio/<series-slug>/`；不要复制 RAW / DNG 原片或旁车文件。
6. 在 `src/lib/portfolio.ts` 中添加记录与已核实的 `exif` 字段，并调整专题地点、年份和编辑顺序。
7. 为新照片增加 EXIF 映射测试，然后运行 `npm run previews` 生成所有响应式预览。
8. 在真实桌面视口检查同行顶边、底边和章节节奏；在手机视口检查单列和横向溢出，并在灯箱中核对 EXIF 顺序与文案。
9. 完成下方全部质量检查后才能提交。
